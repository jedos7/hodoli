# 내 조건 자동매수

## 사용

`/auto-buy.html`에서 종목명 검색 또는 코드 입력 → 지정가와 수량 입력 → 매수 대기 마지막 날 선택 → 종목·금액 확인 → 계좌·주문 내용에 동의 후 **직접 켜기**.

- 기본 입력은 비어 있다. 삼성전자 예시는 placeholder일 뿐 저장된 계획이 아니다.
- 기준은 KRX 최신 체결가 ≤ 사용자 지정 가격. 조건 충족 시 해당 가격으로 현금 보통 지정가를 한 번 요청한다. 돌파 매수나 시장가 매수는 아니다.
- 최대 원금은 가격 × 수량이며 수수료는 별도다. 미수불가 주문가능 금액·수량(`kt00011`)을 확인 단계와 전송 직전에 확인한다. 다른 켜진 매수 계획의 대기 금액도 포함한다.
- KRX 연속매매, 최신 10초 이내 시세, 15:20 이전에만 새 주문한다. 대기 마지막 날 15:20 이후에는 재무장하지 않으면 다음날 주문하지 않는다. 종목은 코스피·코스닥 주식, 정상 거래 상태로 제한한다.
- 같은 종목의 호라이즌/내 조건 자동매도 또는 미확정 주문이 있으면 시작하지 않는다. 다른 종목의 전략·기준은 바꾸지 않는다.
- 새 미체결 매수 주문이 남아 있으면 다음 매수 주문을 보내지 않는다. 응답 불명은 자동 재전송하지 않는다.

## 익절·손절 선택 연결

- 연결 체크박스와 퍼센트 입력은 선택이며 기본 꺼짐이다. 확인 화면에서도 별도 동의를 받는다.
- 연결은 기존 보유가 없는 종목만 지원한다. 기존 보유 종목을 추가 매수할 때는 연결 없이 매수하고 체결 후 자동매도를 직접 설정한다.
- 선택한 익절/손절을 실제 현금 평단에 적용하며 체결 수량 전체를 시장가 매도한다. 보유기간 청산은 없다.
- 매수 원 주문의 잔량이 0이고, REST 잔고와 실시간 잔고가 체결 수량·평단에 일치해야 연결한다. 일부 체결 + 잔량 대기 동안은 체결 수량도 자동매도 감시 전이다.
- 주문 종료 확인 후 60초 이내 잔고 일치를 확인하지 못하면 자동 연결을 중단한다. 다음날 또는 재시작 후 자동 연결하지 않는다.
- 매수 후 연결한 계획은 `내 조건 자동매도`에서 관리한다. 연결 완료 후 매수 화면의 중지는 이미 연결된 자동매도를 끄지 않는다.

## 중지 / 취소 / 삭제

- **매수 대기 중지**: 새 매수 및 아직 연결 전인 자동매도를 중지. 증권사 접수 주문은 남는다.
- **미체결 잔량 취소**: 사용자가 원 주문·종목 확인 후 클릭하면 `kt10003`으로 원 주문 잔량 전체 취소를 1회 요청. 체결 수량은 유지. 자동매도 후속 연결을 해제한다. 취소 응답 불명·거부 시 자동 재전송하지 않으며 키움에서 직접 확인한다.
- **계획 삭제**: 중지/완료 상태이고 미확정 주문이 없는 정확한 plan ID만 삭제. 주문·체결 이력과 보유 주식은 유지.
- 서버 재시작, 계좌 재연결, 절전·시계 변경은 재확인과 사용자 재활성화를 요구한다. PC가 꺼져도 증권사에 접수된 주문은 체결될 수 있다.

## 구현과 검증

- 매수는 `app/auto_buy.py`, `app/auto_buy_service.py`, `app/kiwoom/buy_orders.py`와 계좌/환경별 `data/auto_buy_<hash>.json`으로 분리.
- 호라이즌과 직접 설정 자동매도의 전략 파일은 수정하지 않음. 구성 단계에서 상호 충돌 방지 어댑터와 기존 계좌 피드의 이벤트만 공유한다.
- 저장 잠금 및 원자적 교체. 전송 전 intent 저장. 인증·요청 대기 직후 다시 중지/연결/종목 충돌 확인. HTTP timeout/429/500/auth 실패를 주문 재시도에 사용하지 않음.
- 원 주문번호·종목·매수 구분·가격·수량이 일치한 상세 조회만 체결 판정에 사용. 미체결 목록에서 사라진 것만으로 체결 판정하지 않음.
- 루프백 호스트·Origin·세션 토큰 검증. UI 확인은 90초 유효. POST 전후 오래된 상태 조회 응답 무효화. 조회 단절 시 감시 상태 미확인 표시.
- 2026-09-22: 자동매수/자동매도/계좌/WS/호라이즌 관련 Python 테스트 **252개 통과**, 신규 및 기존 UI 가짜 API 테스트 통과, 실제 브라우저에서 준비·금액·중지·오류 로그 확인.
- 검증은 가짜 증권사/별도 복사본에서 수행했다. **실전 및 증권사 모의 계좌의 실제 주문·체결은 시험하지 않았다.** 삼성전자 매수 계획도 실계좌에 등록하지 않았다.

공식 API 필드 확인 자료: https://raw.githubusercontent.com/Kiwoom-Securities/Kiwoom-REST-API/main/kiwoom/_data/kiwoom_api_spec.json

## 적용

현재 실행 중인 서버에 새 라우트를 로드하려면 재시작이 필요하다. 다른 활성 감시가 있으면 임의로 끄지 않는다. 적용 전 상태를 재조회하고 승인된 감시만 중지한 뒤, 정확한 포트 8000 프로세스를 확인하여 재시작한다. 재시작 후 실제 자동매수/자동매도 활성화는 사용자가 직접 수행한다.
