# 🌅 호라이즌존 자동매수 (변성환 규칙)

화면: `http://127.0.0.1:8000/horizonbuy.html` (관제탑의 **🌅 호라이즌 자동매수** 버튼).
코드: `app/horizonbuy.py` · `app/horizonbuy_service.py`. 판정은 관제탑(`app/horizon.py`), 매도는 기존 자동매도(`app/horizon_plan.py`)가 그대로 맡습니다.

```
관제탑 판정            이 모듈              기존 자동매도
기준봉 → D+1 → D+2  →  12:00 매수  →  체결  →  +15%/70% · −10% · 트레일링 · 청산날
(app/horizon.py)      (horizonbuy)        (horizon_plan.py)
```

## 하루 흐름 (평일, 서버가 떠 있을 때만)

| 시각 | 하는 일 |
|---|---|
| 12:00:00~12:00:59 | 관제탑이 **"정오 조건 충족"(status=ready)** 으로 올린 자리 중 매수 거름망을 통과한 것을 삽니다 |
| 12:05 | 체결 조회 → 체결 수량을 보유로 등록 → **호라이즌 자동매도에 연결**(설정으로 끌 수 있음) |
| 이후 | 매도는 자동매도가 맡습니다. 이 모듈은 더 주문하지 않습니다 |

자동매수를 켜 두면 관제탑 수집이 자동으로 시작됩니다(12:00 판정에 분봉이 필요하므로).

## 사는 조건

**관제탑 판정** (문서 그대로, 이미 구현돼 있던 것)
- 기준봉 D0: 상한가형(+29%↑ · 종가가 고가의 99.5%↑ · 대금 100억↑) 또는 대금폭발형(+15%↑ · 대금 300억↑ · 직전 20일 평균의 5배↑)
- 앞 10거래일 안에 다른 기준봉이 있으면 제외
- D+1: 고가가 D0 종가 +15% 미만 · 12시 이후 15분봉 기울기 ±0.1%/봉 안 · 오후 폭 5% 안 (단 마감이 D0 종가 위면 통과)
- D+2 오전: D+1 저가를 한 번도 안 깸 · 오전 폭 4%↑
- 등급 S / A / B (시총 3,000억 · 기준대금 1,000억 · 상대강도 −3%p · 첫 한 시간 대금)
- 거래정지·관리종목·불성실공시·정리매매 제외

**이 모듈의 매수 거름망** (문서의 "이것만 삼")
- 주가 1,000원 이상
- **기준봉 대금 1,500억 이상** (화면에서 조절)
- 등급이 S·A·B 중 하나

## 수량

- 문서: **S는 두 칸, A·B는 한 칸.** 화면의 "한 자리 금액" × 자리 수가 예산입니다.
- 그 예산을 총 투입 상한 잔여 → 호가 총잔량 → 키움 주문가능 수량 순으로 깎습니다.
- 총 투입 상한 **999만 원 이하**, 자리 수 **5 이하**를 코드에서 막습니다.
- 같은 12:00 묶음 안에서 아직 체결 확인 전인 주문 금액도 총액에 포함합니다(`committed()`). 이게 없으면 한 번에 여러 종목을 살 때 상한이 뚫립니다.

## 문서와 다르게 한 것

| 항목 | 문서 | 이 구현 | 이유 |
|---|---|---|---|
| 주문 방식 | "12:00에 한 번에 삼"(방식 없음) | 매도1호가 **+2틱 지정가** | 시장가로 쓸어 담지 않으려고. 종가배팅과 같은 방식 |
| 자금 | 미수 2.5배 | **현금만** | 상한이 999만 원이라 레버리지가 무의미하고 위험 |
| 칸 나누기 | 예탁자산 × 배수 ÷ 2 | 화면에서 "한 자리 금액"을 직접 입력 | 소액 운용에 맞춤. S는 그 두 배 |
| 우선순위 | 🌅 → 🗻 → 🔥 → 🌙 한 계좌 2칸 | 호라이즌존·종가배팅이 각자 상한을 가짐 | 나머지 둘(대장 눌림목·기준봉 종가)은 안 만들었음 |

## 모드와 안전장치

- **흉내(dry)**: 같은 시각에 같은 판정을 하고 주문은 보내지 않습니다. 자동매도 연결도 하지 않습니다. 기본값.
- **실전(live)**: 실전 계좌(KIWOOM_ENV=real)에서만, 화면 확인란을 선택해야 저장됩니다.
- 전송 전 저널 기록 → 전송 1회. 응답 불명은 재전송하지 않고 그 종목을 잠급니다.
- 관제탑 자리 조회가 실패하면 **사지 않고** "못 샀다"를 남기고 텔레그램으로 알립니다(빈 목록을 '자리 없음'으로 착각하지 않게).
- 자동매도 연결에 실패해도 보유는 그대로 남고 텔레그램으로 알립니다. 자동매도 화면에서 직접 켜면 됩니다.
- 종가배팅·내 조건 자동매수/매도에 걸린 종목, 이미 계좌에 있는 종목은 사지 않습니다.
- 비상 정지는 새 매수만 막습니다. 이미 산 종목은 자동매도가 계속 들고 갑니다.
- **차단기**: 예탁자산 아침 대비 −12% · 주문 거부 6건이면 **새 매수만** 멈춥니다. 매수 건수·금액·같은 종목 되풀이도 막습니다 ([BREAKERS.md](BREAKERS.md)).
- 서버 재시작 후에도 설정·보유는 유지되고, 같은 날 두 번 사지 않습니다.

## 성적 (제작자 자료, 우리 계좌 성과 아님)

기준봉 대금 1,500억 이상 73자리 · 건당 +7.2% · PF 9.4 (2025-09~2026-10). 장세별로는 모든 칸에서 PF 3.4 이상으로 네 매매법 중 가장 고르게 좋았고, 예탁금이 20일 동안 9.7% 넘게 늘 때가 가장 좋았습니다(24번 PF 49).

검증 기간이 1년 남짓이고 2~4일 들고 가므로 갭 손실이 날 수 있습니다. 원본은 [호라이즌_매매법_넷.html](호라이즌_매매법_넷.html)과 [장세와 매매 성적.html](장세와%20매매%20성적.html)에 그대로 보관돼 있습니다.

## API

`GET /api/horizonbuy` 상태 · `POST /api/horizonbuy/settings` · `POST /api/horizonbuy/stop` 비상 정지 · `POST /api/horizonbuy/preview` 지금 자리 미리보기(11시 미리보기 포함, 저장·주문 없음) · `POST /api/horizonbuy/reconcile`. 로컬 주소·같은 출처·화면 토큰만 받습니다. 저장 파일 `data/horizonbuy_<계좌해시>.json`.

테스트: `tests/test_horizonbuy.py` 14개 (거름망·S 두 자리·설정 한도·정오 시간창·흉내 전 과정·실전 전송 1회→체결→자동매도 연결·연결 실패·총액/자리 상한·응답 불명 재전송 차단·재시작·비상 정지·다른 엔진 충돌·거부·자리 조회 실패).
