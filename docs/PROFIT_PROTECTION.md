# 내 조건 자동매도: 이익보전

- `/custom-exit.html` → 잔고 읽기 → 보유 종목 선택 → 이익보전 설정.
- 고정 기준 가격 **미만**인 최신 KRX 체결가가 들어오면 확인한 잔고 전량을 시장가 매도 요청한다. 같은 가격에서는 발동하지 않는다.
- 예: 83,800원 설정 → 83,800원에서는 대기, 83,800원 아래에서 전량 요청. 감시를 켤 때 이미 그 아래이면 새 시세 수신 후 바로 요청할 수 있다.
- 고점을 따라 가격을 높이는 추적 매도가 아니다. 실제 시장가 체결가는 기준가와 다를 수 있다.
- 익절·손절과 함께 설정할 수 있다. 이익보전 기준가가 익절 목표가보다 높아 조건이 겹치면 거부한다. 손절과 동시에 충족하면 이익보전 전량 매도를 우선한다.
- 일부 수량 익절 주문이 모두 체결되고 REST 잔고와 계좌 이벤트가 일치하면, 남은 잔고 **전부**에 대해 이익보전을 이어간다. 미체결 수량이 있으면 후속 주문을 보내지 않는다.
- 이익보전 주문은 한 계획에서 한 번만 요청한다. 접수와 체결을 구분하고, 일부 체결·응답 불명 주문을 중복 전송하지 않는다.
- 수동 매매로 수량/평단이 바뀌거나, 서버 재시작·연결 중단·저장 실패가 발생하면 감시가 중지된다. 변경된 잔고를 다시 확인하고 켜야 한다.
- 조건 확인은 준비 상태만 저장한다. 실제 감시 시작은 사용자가 화면에서 별도 확인 후 켠다. 새 이익보전 체크박스는 기본으로 꺼져 있다.
- 호라이즌의 +15% / −10% / D+2 규칙은 변경하지 않는다. 기존 내 조건 퍼센트 계획과 자동매수 연계 계획은 그대로 호환된다.

## 검증

`tests/test_profit_protection.py`는 가짜 브로커로 가격 경계·전량·중복 방지·익절 후 잔고 확인·우선순위·유효성·연결/시세/잔고 이상·저장/재시작·기존 계획 호환을 검사한다.
`tests/test_profit_protection_ui.cjs`는 메모리 API로 화면 입력·확인·주문 이력·활성화 분리를 검사한다. 실계좌 주문 시험은 수행하지 않는다.
